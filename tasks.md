# Техническое задание: Система звуковых уведомлений для веб-приложения

## Бизнес-требование

Необходимо реализовать механизм проигрывания звуковых уведомлений в веб-приложении при приближении времени начала
следующего этапа или начала/окончания встречи. Страница должна оставаться активной в фоновом режиме, а таймер должен
работать с абсолютной точностью.

## Описание задачи

Создать систему звуковых уведомлений, которая:

- Информирует пользователя о приближающихся событиях (начало/окончание этапа/встречи).
- Гарантирует проигрывание звуков только один раз для каждого события.
- Поддерживает точное воспроизведение таймера, даже если вкладка была в фоне.
- Учитывает ограничения браузеров на автоплей и предотвращение засыпания вкладки.

## Архитектурный подход

1. **Логика уведомлений**:
    - Использовать сравнение текущего системного времени с меткой времени события для определения моментов проигрывания
      звуков.
    - Гарантировать уникальность проигрывания каждого звука для события.

2. **Предотвращение засыпания вкладки**:
    - Реализовать цикличное воспроизведение файла `silent.mp3` (абсолютная тишина) для поддержания активности вкладки.
    - Обеспечить корректное микширование звуков, чтобы фоновая "тишина" не влияла на основные уведомления.

3. **Точность таймера**:
    - Отказаться от инкремента/декремента внутри `setInterval`.
    - Использовать `Date.now()` для сравнения с временными метками событий.

4. **Политика автоплея**:
    - Реализовать механизм инициализации аудио-контекста по клику пользователя (например, кнопка "Подключиться к
      встрече"
      или "Включить звук").

## Шаги реализации для программиста

### Логика React-компонента

1. **Добавьте обработку звуковых уведомлений в TimerScreen**:
    - Используйте существующий контекст `useMeeting` для доступа к времени начала/окончания встречи и этапов.
    - Добавляйте логику проигрывания звуков в компонент `TimerScreen`.

2. **Определите события**:
    - События: начало/окончание этапа/встречи и их временные метки.
    - Сравнивайте текущее время с метками событий и триггерьте звуковые уведомления.

3. **Состояния**:
    - `isAudioReady`: флаг, указывающий, что аудио-контекст инициализирован.
    - `isActive`: флаг активности таймера.

### Работа со звуком

1. **Инициализация аудио-контекста**:
    - Создайте экземпляр `AudioContext` или `webkitAudioContext` при первом клике пользователя.
    - Обработайте ошибки и предложите пользователю включить звук.

2. **Цикличное воспроизведение `silent.mp3`**:
    - Запустите цикл, который воспроизводит `silent.mp3` раз в секунду.
    - Используйте `setInterval` с проверкой текущего времени, а не инкремента.

3. **Проигрывание уведомлений**:
    - За 60 секунд до события воспроизведите `warn.mp3`.
    - В момент события воспроизведите `error.mp3`.
    - Обеспечьте уникальность проигрывания (используйте флаги или множества для отслеживания воспроизведенных звуков).

4. **Обработка фонового режима**:
    - При выходе из фона проверяйте, не наступили ли одновременно два события (например, <60 сек и 0 сек).
    - Приоритет отдавайте `error.mp3`.

## Критерии приемки (DoD)

1. **Функциональность**:
    - Звуковые уведомления проигрываются за 60 секунд и в момент события.
    - Каждый звук проигрывается только один раз для события.
    - Таймер работает точно, даже если вкладка была в фоне.

2. **Предотвращение засыпания вкладки**:
    - Вкладка остается активной в фоновом режиме.
    - Фоновый звук (`silent.mp3`) не влияет на основные уведомления.

3. **Политика автоплея**:
    - Аудио-контекст инициализируется только по клику пользователя.
    - Пользователь получает уведомление о необходимости включить звук.

4. **Качество кода**:
    - Код соответствует стандартам проекта.
    - Компоненты и хуки хорошо документированы и тестируемы.
    - Нет утечек памяти или неиспользуемых ресурсов.
